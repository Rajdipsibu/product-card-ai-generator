# AI Product Card Generator

A full-stack web application that generates product titles, descriptions, and keywords from a product name and category using an AI API.

## Features

- Enter a product name and select or enter a product category.
- Generate a product title, short description, and relevant keywords.
- View the generated details in a styled product card.
- Loading and error states to communicate API progress and failures.
- Responsive interface built with React and Tailwind CSS.

## Tech Stack

**Frontend**
- React
- TypeScript
- Tailwind CSS
- Vite

**Backend**
- Node.js
- Express
- TypeScript
- REST API

**AI**
- Google Gemini API (configured through an environment variable)

## Design Choices

### 1. Separate frontend and backend

The project uses separate `frontend` and `backend` applications. This keeps UI code independent from API and AI integration logic, making each side easier to maintain and test.

### 2. React with TypeScript

React manages the form, loading state, errors, and generated product details. TypeScript interfaces define the expected product and API response shapes, helping catch type-related mistakes during development.

### 3. Express REST API

The frontend sends the product name and category to `POST /api/products/generate`. The backend validates the input before requesting generated content. Keeping the AI request on the server means the API key does not need to be exposed to the browser.

### 4. Tailwind CSS

Tailwind utility classes are used to build a responsive layout and product-card preview without maintaining a large collection of separate CSS rules. The card emphasizes the generated title, description, category, and keyword tags.

### 5. Environment-based configuration

API keys and environment-specific settings are loaded from `.env` files rather than hard-coded into the source. The `.env` files should never be committed to Git. Use the provided `.env.example` files as templates.

## Where AI Is Used

AI is used in the backend service (`backend/src/services/ai.service.ts`) to transform the supplied product name and category into structured product-card content.

The backend sends a prompt to the configured Gemini API requesting:
- `title`: a concise, product-focused title.
- `description`: a short description suitable for a product card.
- `keywords`: a list of five relevant keywords.

The service requests a JSON response and parses it into the application's expected data structure. The generated values are then returned by the Express endpoint and displayed in the React UI.

AI is **not** used to build the interface, manage React state, or validate required form fields. Those parts are implemented with regular application code. AI-generated text may need review before being used in a real product listing.

> Note: AI generation depends on API availability, account access, and usage limits. If the provider returns an error, the app displays an error state so the user can try again.

## API Endpoint

### `POST /api/products/generate`

**Request body**
```json
{
  "productName": "Wireless Headphones",
  "category": "Electronics"
}
```

**Successful response shape**
```json
{
  "success": true,
  "message": "Product details generated successfully.",
  "data": {
    "title": "Wireless Headphones for Everyday Listening",
    "description": "Enjoy clear sound and comfortable listening at home or on the go.",
    "keywords": [
      "wireless audio",
      "Bluetooth headphones",
      "portable sound",
      "music",
      "everyday listening"
    ]
  }
}
```

The example content above is illustrative; actual results are generated by the configured AI model and may differ.

## Getting Started

### Prerequisites

- Node.js and npm
- A Gemini API key with access to a supported model

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/product-card-ai-generator.git
cd product-card-ai-generator
```

Replace `YOUR_USERNAME` with your GitHub username.

### 2. Set up the backend

```bash
cd backend
npm install
```

Create `backend/.env` using `backend/.env.example` as a guide:

```dotenv
PORT=5000
FRONTEND_URL=http://localhost:5173
GEMINI_API_KEY=your_api_key_here
```

Start the backend in development mode:

```bash
npm run dev
```

The API should run at `http://localhost:5000`.

### 3. Set up the frontend

Open a second terminal from the project root:

```bash
cd frontend
npm install
```

Create `frontend/.env` using `frontend/.env.example` as a guide:

```dotenv
VITE_API_URL=http://localhost:5000/api
```

Start the frontend:

```bash
npm run dev
```

Open the local URL printed by Vite, usually `http://localhost:5173`.

### 4. Check the backend health endpoint

Open `http://localhost:5000/api/health` in your browser. The endpoint should return a health response if the backend is running.

## Current Limitations

- Generated content depends on the configured AI provider and its rate limits.
- The application does not persist generated product cards to a database.
- Generated content should be reviewed for factual accuracy before publication.
- Add your repository URL and, if available, a deployed demo URL before submitting.

## Future Improvements

- Allow users to edit and regenerate individual fields.
- Save product cards and generation history.
- Add stronger schema validation for AI responses.
- Add automated tests for the API and UI.
- Deploy the frontend and backend and configure production environment variables.

## Security Notes

- Never commit real API keys or `.env` files.
- Keep the AI API key on the backend; do not prefix it with `VITE_`.
- Configure allowed CORS origins for production rather than allowing every origin.
